# [abios-evidence] Issue #413 — fix(fleet): -AutoClean teardown kills tab shell and deletes worktree folder

## What was tested

Two new pure/thin functions added to `BoardWork.Processes.ps1`, and the teardown logic
changed in `Invoke-SessionCleanup` (Board-Work.ps1):

1. `Find-WtTabShellCore` — pure function: from a `{ProcessId, CommandLine}` list, returns
   the first process whose command line matches `launch-<n>.ps1` for a given issue number.
   Exact match prevents touching a shell for any other issue.
2. `Find-WtTabShell` — thin CIM wrapper; mockable in tests via Pester's `Mock`.
3. `Invoke-SessionCleanup` — for `wt` sessions: calls `Find-WtTabShell`, kills the shell via
   `Stop-ProcessTree` (with the 500 ms OS-release wait), then after `git worktree remove`
   tries `Remove-Item` on any surviving folder.

## Key decisions

- `Find-WtTabShell` is a separate thin function (not inlined into `Invoke-SessionCleanup`)
  so tests can mock it without mocking `Get-CimInstance` globally.
- The 500 ms `Start-Sleep` is placed INSIDE the `if (-not $DryRun)` block (only runs in
  real teardown, never in DryRun or tests).
- `Remove-Item -ErrorAction SilentlyContinue` so a still-locked folder (e.g. another tool)
  produces a NOTA log entry, not a thrown error.
- The "asks git, not the disk" integration tests received `Mock Find-WtTabShell { return $null }`
  in BeforeEach so they stay deterministic and don't call real CIM in CI.
