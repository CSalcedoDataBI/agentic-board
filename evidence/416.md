# [abios-evidence] — Issue #416: DeepWiki MCP integration

## What was tested

Three acceptance criteria per the issue and expert brief:
1. Catalog entry installs the DeepWiki MCP server through the normal `/tools` flow.
2. `/docs deepwiki` reports indexed status correctly for indexed, not-indexed, and private repos.
3. The public-repos-only limit is documented at the point of use.

### B. `/docs deepwiki` status reporting (acceptance criterion 2)

**Command:** `Invoke-Pester plugins/agentic-board/tests/Get-DeepWikiStatus.Tests.ps1 -Output Minimal`

**Result:** 20/20 passed.

Scenarios covered:
- Private repo → `private` status ✅ (`reports private status when OverrideIsPrivate is true`)
- Indexed public repo → `indexed` status ✅ (`reports indexed when HTTP 200 and body has no not-indexed markers`)
- Not-indexed public repo → `not-indexed` status ✅ (`reports not-indexed when HTTP 200 and body has not-indexed markers`)
- Network failure → `unknown` status ✅ (`reports unknown when HTTP probe returns non-200`)
- HTTP 0 (no response) → `unknown` status ✅ (`reports unknown when HTTP probe returns 0 (no response)`)

### C. Public-repos-only limit documented at point of use (acceptance criterion 3)

Verified in:
- `commands/docs.md` — "PUBLIC REPOS ONLY. DeepWiki indexes only public GitHub repositories." as a heading in the `/docs deepwiki` section.
- `Get-DeepWikiStatus.ps1` — `PUBLIC REPOS ONLY` line printed on every public-repo output; private repos print `Private repos require a paid Devin subscription`.
- Test: `always includes PUBLIC REPOS ONLY notice in text output for public repos` ✅
- Test: `private status message mentions public repos and Devin` ✅
